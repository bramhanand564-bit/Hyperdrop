# AI App Builder\n\nHyperdrop's creator now uses an automatic build-target router.\n\n## Targets\n\n### SINGLE_HTML\nThe default and smallest target. The AI creates a complete self-contained index.html with inline CSS and JavaScript. It is previewed directly in the app WebView and can be iterated through chat.\n\n### ADVANCED_PROJECT\nUsed automatically when the request needs native/platform capabilities or when the AI determines that a single HTML file cannot reliably satisfy the requirement. The project stores source files and MEMORY.md and is the foundation for future native Android packaging.\n\n## Chat workflow\n\n1. User describes an app.\n2. The builder routes the request to the simplest viable target.\n3. AI creates the real app/source, not just a description.\n4. The app is rendered in a live preview.\n5. User asks for changes in natural language.\n6. AI receives the existing source and project memory before every change.\n7. A version snapshot is stored so changes can be undone.\n\n## Project memory\n\nEvery generated project contains a MEMORY.md representation. For single-file apps, the canonical runtime remains index.html, while MEMORY.md travels with the project metadata and version snapshots.\n\n## Security\n\nGenerated single-file apps must not contain API keys or other secrets. Advanced integrations should use scoped secure services or a backend/proxy rather than embedding credentials in exported HTML.\n\n## Future build stages\n\n- richer source/file editing for Advanced projects\n- native Android project generation\n- Gradle/APK/AAB build pipeline\n- migration from Single HTML to Advanced Project when new requirements need native capabilities\n- asset management and project export/import
- remote build-service handoff for running Android builds from an exported advanced project
